# Motion Prompt 中文动效库

本技能是 Shohei Ohtaki 的 Motion Prompt 的非官方简体中文版；技能标识为 **motion-prompt-zh**，与原版 `motion-prompt` 共存。默认 `zh-Hans`，`zh` 等价；保留 `en`、`ja`。不安装或覆盖其他技能，不改全局 Agent 配置。

用本文件所在目录的脚本执行命令。下文 `<skill-dir>` 指实际选中技能目录，不是用户项目目录；在目标项目中工作时也使用这个路径。

```sh
node <skill-dir>/scripts/motion-prompt.mjs info
```

`info` 是数据来源和可用性的依据，不能凭技能中记忆的数量或名称编造效果。完整源码仓库优先读取本地 `api/v1`；独立安装读取随技能分发的 `scripts/site-config.json` 中的中文版 API；可用 `MOTION_PROMPT_BASE` 显式指定本地目录或逗号分隔的 URL。配置站点不代表已经上线。脚本在中文资料缺失时报错，备用来源与缓存会明确提示，不能把原作者英文数据假装成中文版。

## 根据用户意图调用

| 用户需求 | 行动 |
|---|---|
| “打开 Motion Prompt 中文动效库”“帮我挑选几个适合首页的动画”“有哪些适合数据看板的 UI 动效” | 运行 `pick`，按上下文可加 `--pack lp` 或 `--pack ui`；让用户实际选择 |
| “搜索与文字入场有关的动画” | `search 文字 入场 --lang zh-Hans`；需要直观比较时再打开库 |
| “使用 #012 实现这个动效” | `get 012 --lang zh-Hans`，再读取其 `kit` 并实现，无需额外打开选择页 |
| “把我刚刚选中的动画用到当前项目”或粘贴的选择结果、分享链接 | 以回传/粘贴的编号及顺序为准，读取 `get` 和 `kit`；没有实际选择数据时先取得选择，不猜编号 |
| “将 #032 的镜头运动整理成视频生成提示词” | 读取 `get 032`、`prompt 032`，按目标模型写文字提示词，不把 Canvas 代码当作提示词 |

| 命令 | 用途 |
|---|---|
| `info` | 数据来源、目录版本、元素数量、缓存与配置站点 |
| `list` / `list --pack ui` | 分类总览或单包所有动画 |
| `search 弹性` / `search typewriter text` / `search 文字 登場 --lang ja` | 中英日名称、分类、解释、描述、别名和英文标签；支持 `--pack`、`--limit` |
| `get 012 045 --lang zh-Hans` | 读取规格与原始参考代码；每次最多 8 项，接受数字、#编号或演示链接 |
| `kit motion` | 该包共享常量和辅助代码，每包只读一次；保持原代码标识符和版权行 |
| `prompt 012` | 完整中文 Prompt；`--lang en`、`--lang ja` 获取原语言 |
| `pick --lang zh-Hans` | 打开库并等待回传；源码仓库自动使用本地，独立安装使用配置的线上站点 |
| `pick --local --lang zh-Hans` | 明确要求完整源码提供本地网页 |

`--out <目录>` 可保存 get/prompt/kit 输出；`--refresh` 跳过下载缓存；`MOTION_PROMPT_CACHE`、`MOTION_PROMPT_TTL` 配置缓存。没有网络且本地资料也不可用时，明确说明阻碍，不凭名称实现并冒称使用了目录代码。

## 浏览器选取与交接

1. 使用 `pick --lang zh-Hans`。如果有用户可见的 Codex 浏览器面板，优先 `pick --no-open --lang zh-Hans` 并在面板打开 CLI 打印的**完整 URL**；否则直接 `pick` 请求系统浏览器打开。完整源码可加 `--local`。不得删掉 URL 中的 `cb`、令牌、语言与筛选参数。
2. 告知用户：点击“选择”，可多选并填备注，最后点击“发送给 AI”。CLI 默认等待 900 秒；工具提前返回运行会话时，继续等待该会话输出，不将启动信息当作已收到选择。超时退出码 4 表示本次没有选择。
3. 网页通过原有 `127.0.0.1` 临时监听器、随机令牌和顶层跳转回传编号、备注及语言。CLI 从自己已加载的目录解析中文名称、英文原名、分类、解释、规格和演示链接。普通访问网页使用“复制所选”。不放宽回调地址、Host 或令牌校验，不把项目文件发给站点。
4. 收到选择后继续执行当前用户任务。选择结果只确定效果和备注，不自动授予发布、联网写入或额外功能的权限。只使用选中的效果，按原顺序保留；必要的技术适配不应增加其他效果。

## 在当前项目完成实现

先查看目标项目的框架、现有组件、样式、事件与动画方式，再对选中编号运行 `get`，按其依赖运行 `kit`。开始移植前阅读 [references/porting.md](references/porting.md)，特别是时间控制、多包隔离、曲线映射和版权行。

- React、Vue、原生 HTML/CSS/JS 等 Web 项目：沿用现有组件和状态管理，将演示光标/模拟滚动替换为真实事件；可用 CSS、项目已有动画库、Canvas 等合适技术。保留时间、缓动、位移、缩放、运动顺序和过冲；尊重 `prefers-reduced-motion`。
- 保持已有布局、业务数据、语义与交互；在替换某一段时保持原内容、时段和前后衔接。通常通过调整停留段适配时长，只有动作本身无法容纳时才等比缩放时间并说明。
- 只替换项目相关文字、颜色和素材。需要执行原 Canvas 代码时，每个包置于独立作用域，读取它自己的尺寸和周期；原 `cells[i]`、变量及函数名保持原样，保留元素与 kit 的 MIT 版权行。
- 视频/图片生成模型：按专业名称与规格组织主体、动作、顺序、速度、缓动、构图、风格、比例和时长等文字要求；不要机械粘贴 Canvas 代码。图像模型不需要模拟播放帧；说明生成模型对精确运动数值仅作近似遵循。
- 实现后实际预览或执行适合该项目的检查。最终用中文列出动画 ID、实现位置、代码变化、保留或适配的参数与真实验证结果；无法验证的部分明确标记。
